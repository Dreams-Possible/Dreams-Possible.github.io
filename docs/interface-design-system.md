# Mathrix 界面设计规范

> 状态：实施规范 v0.24 · 2026-09-18
> 适用范围：本站及后续项目展示页面。规范定义视觉与交互的共同语言，不绑定某段文案、某个项目或某一种组件结构。
> 原则：先建立可复用的语义规则，再决定单个页面如何实现。

## 1. 体验目标

界面应像一个可以探索的工程空间：**有深度、能感知操作、始终可读**。借用宇宙的空间尺度、轨道、漫射光和留白感，但不使用火箭、星球、星空壁纸等直接图像作为默认语言。透视与动画要帮助人理解层次和方向，而不是盖过文字。

访问者在数秒内应能辨认页面身份、主要内容和下一步行动；继续浏览时，空间效果逐步展开。阅读区要保持稳定，长期停留也不疲劳。

### 不可妥协的约束

- **文字先于图形**：品牌以 `Mathrix` 文本呈现。现阶段不使用字母徽标或占据主要版面的 Logo。
- **内容永远清晰**：文字不放在持续漂移、严重模糊或高对比粒子穿过的区域。装饰不承载唯一信息。
- **深度有层级**：透视、磨砂、烟雾、粒子、阴影各有职责，不能在同一区域全部叠满。
- **动效尊重用户与设备**：支持减少动态效果、键盘操作、触屏和低性能环境。
- **中英文与明暗主题同等完整**：布局不能只对一种语言或一种主题成立。

## 2. 视觉语法

### 空间层级

所有页面使用相同的四层概念，而不强制使用相同组件：

| 层 | 作用 | 允许的视觉处理 |
| --- | --- | --- |
| 基底 | 建立环境与空间方向 | 低对比色场、细微纹理、稀疏网格或暗示远景的渐变 |
| 环境 | 提供可持续感知的深度 | 缓慢漂移的漫射光、轨迹或少量粒子；不响应内容滚动时也可以轻微活动 |
| 内容 | 承载阅读和操作 | 清楚的文字、稳定的布局、足够的对比度；必要时用半透明表面与背景隔离 |
| 反馈 | 表示焦点、悬停、选择和结果 | 边缘高光、位置/阴影变化、局部透视；只在状态变化时出现 |

一个视口只设一个主要空间焦点。其余区域用密度和对比度做减法。背景细节的亮度必须低于内容和操作反馈。

### 光、材质与纹理

- 光源方向在同一页面内保持一致；阴影和高光要能解释表面的前后关系。
- 磨砂面用于需要与动态背景分离的内容，使用透明度、微弱边线和适度模糊共同表达；文本不能依赖 `backdrop-filter` 才可读，浏览器不支持时要有不透明回退。
- 雾气只作为低对比的朦胧环境色层，不承担主要视觉叙事；纹理若形成明显条带、影响阅读或性能，应退回柔和静态色场，必要时移除。
- 粒子用于传达空间尺度，数量少、运动慢、透明度低。避免满屏随机闪烁。
- 透视网格、轨迹和线框应有明确的消失方向或结构关系，不作为每个区块的重复装饰。
- 环境色场跨页面区块连续存在，内容区用透光表面承接；允许稀疏的雨线和偶发流星作为远景细节，始终低于文字与控件的对比度。
- 天气点缀采用有差异的轨迹和节奏，不使用整齐重复的平铺动画；数量与频率允许用户调整，设置可记忆，数值为零时对应效果停止。

### 色彩与主题

颜色以**语义角色**管理，页面与组件只引用角色，不直接写散落的固定颜色。基础角色：

| Token 角色 | 用途 |
| --- | --- |
| `canvas` / `canvas-raised` | 页面基底与抬升后的环境层 |
| `surface` / `surface-glass` | 阅读表面与透光表面 |
| `text-primary` / `text-secondary` | 主文字与辅助文字 |
| `border-subtle` / `border-active` | 静态边界与交互边界 |
| `accent` / `accent-strong` | 操作、焦点及空间光源 |
| `shadow` / `glow` | 结构阴影与局部发光 |

深色主题以近黑的中性蓝灰为底，冷蓝光只用于少量重点；浅色主题以偏冷的浅底与深蓝文字保持同一身份。主题切换改变的是**明度关系**，不是把所有颜色机械反转。两种主题都要保有远景、表面、文字和反馈四层差异。环境粒子也使用两套独立色板：浅色主题以较深且可见的冷蓝雨线、偏紫红的流星为基调；深色主题以浅青雨线、暖金流星建立层次，不能只复用同一 RGB 值再调整透明度。

实施时先给每个语义角色确定明暗两套值，再在浏览器截图中校验；规范不把具体十六进制值锁死在文档里。正文对比度目标不低于 4.5:1，大号文字与必要的非文字操作边界不低于 3:1。

### 字体与排版

- 品牌名称使用文本字标，通过字重、字距和位置建立识别，不使用单独的 M 图形替代。
- 中文和英文共享相近的视觉重量；标题和正文各自使用一套跨文字系统的字体栈。每个栈把拉丁字体放在前面、中文字体放在后面，让中文界面中的英文和英文界面中的中文也按其字形回退到对应字体；不得只按页面语言给整个 body 指定单一字体。 中文必须使用站点加载的单一网页字体，系统字体只能作加载失败时的末级回退，不能改变正常访问时的视觉风格。字体选择必须在实际页面截图中评审，不能只依据字体名称决定。英文长词、仓库名允许换行，不挤压布局。
- 建立从正文、辅助文字、小标题到主标题的有限字号级别；正文以可读为先，行长尽量控制在约 45–75 个中文字符对应的宽度以内。
- 标题可以形成大尺度对比，但不要靠只给一个词换色或斜体来制造“设计感”。
- 装饰性英文标签、坐标和数字只在传达真实结构或状态时使用，避免虚构参数。

### 共同尺度

初始实现采用有限的尺度，后续通过截图和可用性检查整体调整，避免单个页面随意增加近似值：

| 尺度 | 初始 token 阶梯 | 使用原则 |
| --- | --- | --- |
| 间距 | 4 / 8 / 12 / 16 / 24 / 32 / 48 / 64 / 96 px | 相邻信息用小间距，不同内容组用大间距；不靠新增任意值解决结构问题。 |
| 字号 | 12 / 14 / 16 / 20 / 28 / 40 / 64 px | 正文基准为 16 px；标题在不同视口间用流体尺寸过渡。 |
| 圆角 | 4 / 8 / 16 px | 由表面层级决定，不因组件名称不同而改变。 |
| 深度 | `flat` / `raised` / `floating` | 通过边界、阴影和位移共同表达；同一深度级别在全站一致。 |
| 动效 | `quick` 120–180 ms / `response` 240–400 ms / `ambient` 8–18 s | 操作反馈先于环境动画完成；常驻动画不得产生突兀循环点。 |

实际 CSS 应把这些值集中定义为变量。增加新 token 时说明现有尺度为何不足，并同步检查两种主题。

## 3. 动态规则

动效分为三种，优先级从高到低为**操作反馈 → 滚动叙事 → 环境呼吸**。同一时刻只能有一个高注意力动作。

### 环境呼吸

页面静止时仍可感到轻微生命力：远景光晕缓慢移动、少量粒子沿可解释的方向漂浮、柔和轨迹缓慢改变。周期应长、振幅应小，不闪烁、不频繁循环重置。主阅读区和导航不得持续移动。

### 滚动与文档流

- 首屏与后续内容遵循正常文档流。首页入口允许一个由实际滚动位置直接映射的短滚动叙事：双行主标题可向下一段标题上方迁移，右侧抽象线框可轻微放大；它不能改写滚动距离、拦截输入或把内容重排为不可抵达的状态。
- 首屏文案与项目内容应各自处于稳定、可直接抵达的阅读位置；滚动叙事只能补充方向感，不能要求用户完成动画才能进入内容。其位置必须随真实滚动进度逐帧更新，不使用与滚动脱钩的补间或自动播放。
- 放大线框时检查浏览器滤镜合成造成的模糊和亮度跳变；必要时降低放大幅度，移除背景线框自身的磨砂滤镜，并保持其亮度连续。
- 页面链接、键盘滚动和浏览器后退照常工作；动画观察滚动位置，不拦截滚动输入。
- 移动端降低层数与位移；在性能不足、触屏或减少动态效果环境中可退化为静态纵深。
- 内容进入视口可以有一次有意义的显现，但不把每一张卡片都做同样的淡入上移。

### 操作反馈

可操作表面应明确显示静止、悬停、键盘焦点、按下和选中状态。前景玻璃使用同一个全局指针光场：光点邻近哪个表面，哪个表面才产生局部反光；背景和装饰图层不响应指针。触屏没有悬停，仍需清楚的点击区域与按下反馈。键盘焦点应至少和鼠标悬停一样醒目。

跟随指针的高光在离开时应从当前位置淡出，不能在淡出期间把坐标重置到中心。浅色主题的高光也应是连续的漫射亮度变化，不得用独立的环形边界模拟光晕。深色表面可使用 screen 叠加形成自发光；浅色表面使用普通混合模式及白色主光模拟反射，两者不得共用同一混合模式或色彩配方。邻近表面可以同时接收不同强度的反光，光场强度随距离连续变化。交互表面移动不得导致指针在边缘反复触发进入与离开。

交互强度遵循内容权重：导航和普通文字链接克制，主要入口及可探索表面更强。一个页面不能让所有元素都持续发光、旋转或倾斜。

### 减少动态效果与性能

- `prefers-reduced-motion: reduce` 时停止自动粒子、连续漂移和视差；保留必要的即时状态反馈。
- 页面不可见时暂停连续动画；跨区共享的场景可以在首屏离开视口后继续低强度活动。优先使用 `transform` 与 `opacity`；避免大面积反复计算布局或高成本模糊。
- 持续雾气先离线绘制为透明纹理，运行时只移动与淡化少量图层；不得逐帧模糊全屏画布。雨、粒子等仍需实时绘制的效果要限制像素比和绘制频率。
- 环境动画不能阻塞加载、滚动或输入；低性能设备以静态图层保持视觉完整。
- 无 JavaScript、Canvas 或滤镜时，内容、导航、主题对比和主要入口仍必须可用。

## 4. 响应式与可访问性

- 采用内容驱动断点，不为某个设备型号定制。窄屏只保留一个主要空间焦点，内容按自然阅读顺序排列。
- 透视不能让按钮、文字或可点击区域发生视觉位置与实际点击位置不一致。
- 动画和状态不只靠颜色传达；链接有清楚名称，焦点可见，操作目标在触屏上有足够面积。
- 装饰图层从无障碍树中隐藏；真实信息必须以文本提供。动态更新区域谨慎使用实时朗读，避免频繁打断屏幕阅读器。
- 主题与语言控制应能用键盘操作，状态可被辅助技术识别。
- 偏好控制必须有常驻的可见名称；当前值只表达选择，不承担解释控件用途的职责。选中态保持克制，避免与主要行动争夺视觉权重。

## 5. 中英文与主题行为

### 语言

首次访问默认英文；用户可以手动切换，选择保存在本地，并优先于默认值。界面文案、导航、按钮、空状态、日期格式和辅助技术标签都需要翻译。项目专有名称保留原名，项目简介提供中英两个版本或明确的回退策略。切换语言不改变当前页面与筛选状态。

### 主题

首次访问遵循 `prefers-color-scheme`；用户可手动选择浅色、深色或跟随系统，选择保存在本地。系统偏好变化时，“跟随系统”模式应同步更新。初始绘制要尽量使用正确主题，减少亮暗闪屏。切换主题不刷新页面、不重置随机结果或滚动位置。

## 6. 可持续开发约定

- 将颜色、间距、字号、层级、动效时长和缓动集中为设计 token；组件只使用语义 token。
- 交互状态与动效应有统一的命名和边界，避免新页面各自发明一套“悬停效果”。
- 内容数据、翻译文案与视觉规则分离；新增项目不应要求修改布局代码。
- 每次新增视觉模式，先说明它属于哪一层、表达什么状态，以及明暗主题、移动端和减少动态效果下的行为。
- 验收至少覆盖：中英 × 明暗主题、桌面 × 窄屏、鼠标 × 键盘、正常 × 减少动态效果，以及无滤镜/低性能回退。

## 7. 本轮设计自检

这份规范有意保留“宇宙”的**空间感**，舍弃通用星空背景、密集霓虹、每张卡片都旋转等常见套件化做法。最有记忆点的视觉变化应集中在入口场景和滚动叙事；项目内容区通过材质与交互保持统一，但不与首屏争夺注意力。

规范先约束行为和层级，不把具体项目数、卡片尺寸、按钮文案或页面结构写进核心规则。本站当前改版目标另见 [`site-redesign-brief.md`](site-redesign-brief.md)。
